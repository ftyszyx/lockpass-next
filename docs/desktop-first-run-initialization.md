# PC 客户端首次初始化流程

## 目标

PC 客户端第一次启动时，如果本机没有任何账号，只展示一个极简欢迎页：

```text
欢迎使用 LockPass

[登录]
[创建新账号]
```

这个页面只承担分流职责：

1. 登录：用户已有服务器账号和保险库，要在这台 PC 上恢复并解锁数据。
2. 创建新账号：跳转网站，由网站完成账号创建流程。

PC 客户端不在首屏展示服务器配置、主密码说明、安全密钥说明、同步说明或其它教育信息。复杂信息放到后续步骤中按需出现。

## 首次进入判定

PC 客户端启动后先读取本机 meta 信息：

1. 如果本机没有任何账号，进入首次初始化欢迎页。
2. 如果本机有账号但当前账号没有完整加密资料，继续该账号的恢复流程。
3. 如果本机有账号且加密资料完整，跳过初始化，直接进入解锁页。

本机 meta 信息只用于判断本机状态和账号列表，不能保存主密码、安全密钥明文、`unlockKey`、`vaultKey` 或明文条目。

## 首屏

首屏内容：

1. LockPass 图标。
2. 欢迎标题。
3. 登录按钮。
4. 创建新账号按钮。

按钮优先级：

1. 登录是主按钮。
2. 创建新账号是次按钮。

首屏不显示：

1. 服务器下拉框。
2. 邮箱输入框。
3. 主密码输入框。
4. 安全密钥输入框。
5. 说明卡片、功能卖点、保存状态、调试信息。

## 登录已有账号流程

用户点击“登录”后，进入已有账号恢复流程。

### 1. 输入邮箱和服务器

页面收集：

1. 邮箱地址。
2. 服务器类型：LockPass 官方托管或自建服务器。

如果选择 LockPass 官方托管，使用内置官方服务器地址。

如果选择自建服务器，必须让用户输入服务器地址：

1. 没有默认自建地址。
2. 没有 fallback 到 `localhost` 或开发地址。
3. 地址为空或格式无效时不能进入下一步。
4. 用户确认后，可以把该服务器地址保存到本机 meta，后续登录同一账号时复用。

这一页的目标是定位服务器账号和服务端位置，不做主密码校验。

### 2. 输入主密码和安全密钥

下一步后，页面要求用户输入：

1. 主密码。
2. 安全密钥 / Secret Key。

用户可见文案必须使用“安全密钥 / Secret Key”，不要写“恢复密码”。代码和协议中仍可以使用 `recoveryKey` 字段名。

这一页的目标是本地解锁服务端密文：

```text
unlockKey = Argon2id(domain("lockpass unlock v1") || encoded(主密码) || encoded(recoveryKey), kdfParams)
vaultKey = AEAD_Decrypt(key = unlockKey, ciphertext = wrappedVaultKey, aad = vaultKeyAAD)
```

主密码和安全密钥只在 PC 客户端本地内存中短暂存在，不能上传服务器，不能写入日志、URL、普通配置、SQLite 明文字段或崩溃报告。

### 3. 拉取用户数据

用户提交主密码和安全密钥后，PC 客户端执行：

1. 使用邮箱和服务器地址请求服务器账号信息。
2. 获取该账号的 `wrappedVaultKey`、KDF 参数和密文快照。
3. 在本地使用主密码和安全密钥派生 `unlockKey`。
4. 解开 `wrappedVaultKey` 得到 `vaultKey`。
5. 使用 `vaultKey` 解密密文对象。
6. 将密文对象保存到本机账号目录。
7. 将安全密钥保存到系统安全存储。
8. 绑定当前设备并保存 `deviceToken` 或 token handle。
9. 进入保险库页面。

服务端只能返回密文和元数据。服务端不能验证主密码是否正确；主密码错误或安全密钥错误时，表现为客户端无法解开 `wrappedVaultKey`。

### 4. 登录失败状态

失败需要分清楚原因：

1. 邮箱不存在：提示账号不存在，可引导创建新账号。
2. 服务器不可达：提示检查服务器地址或网络。
3. 没有可用密文资料：提示该账号还没有创建保险库或服务端数据不完整。
4. 主密码或安全密钥错误：提示主密码或安全密钥不正确。
5. 设备绑定失败：提示登录成功但设备授权失败，可重试。

不要把所有失败都显示成“登录失败”。

## 创建新账号流程

用户点击“创建新账号”后，PC 客户端打开网站创建账号页面。

创建新账号必须在网站上完成，流程见 `web-account-creation-flow.md`：

1. 输入姓名和邮箱。
2. 输入邮箱验证码。
3. 设置主密码。
4. 生成 Secret Key。
5. 备份 Secret Key。
6. 完成账号创建和设备绑定。

PC 客户端职责：

1. 打开官方托管或用户选择的自建服务器网站。
2. 在 URL 中携带桌面端绑定参数，例如 `desktopBind=1`、`clientDeviceId`、`deviceName`。
3. 等待网站通过 deep link 回调。
4. 接收账号、设备和 `deviceToken` 信息。
5. 后续按网站创建结果进入本机保险库初始化或拉取数据流程。

网站创建账号时也必须遵守同一安全边界：

1. 主密码不上传服务器。
2. Secret Key 不上传服务器。
3. 服务器只保存邮箱、账号、设备、`wrappedVaultKey`、KDF 参数和密文对象。

## 初始化完成后的再次启动

初始化完成后，本机已经有服务器账号、加密资料和系统安全存储中的安全密钥。软件再次启动时：

1. PC 客户端读取本机 meta 信息。
2. 如果当前本机账号存在且加密资料完整，直接显示解锁页。
3. 默认选中上次使用的账号。
4. 用户输入主密码。
5. PC 客户端从系统安全存储读取安全密钥。
6. 使用主密码和安全密钥派生 `unlockKey`。
7. 解开 `wrappedVaultKey`，得到 `vaultKey`。
8. 加载并解密本机保险库数据。
9. 进入保险库页面。

如果系统安全存储不可用，或这台设备没有保存安全密钥，解锁页应提供手动输入安全密钥的入口。用户手动输入并成功解锁后，可以再次把安全密钥保存到系统安全存储。

如果本机保存了多个账号，启动时默认进入当前账号的解锁页；用户可以进入账号选择，切换到其他本机账号。切换账号必须先锁定当前会话并清理当前账号的会话密钥。

## 本机保存内容

可以保存：

| 位置 | 内容 |
| --- | --- |
| 本机 meta | 账号 id、邮箱、显示名、服务器模式、服务器地址、当前设备 id、保存游标、加密参数、`wrappedVaultKey`、本机账号列表 |
| 本机加密对象库 | 保险库、条目、附件索引和附件密文 |
| 系统安全存储 | 安全密钥；受信任设备快速解锁材料 |
| 服务器 | 账号、邮箱验证状态、设备、设备 token hash、密文对象、版本元数据 |

禁止保存或上传：

1. 主密码明文。
2. 安全密钥明文到普通 app data、服务器、日志或备份明文。
3. `unlockKey`。
4. `vaultKey` 明文。
5. 条目、附件文件名、备注、URL、字段值等明文。
6. 服务器长期密码凭据。

## UI 状态摘要

```text
无本机账号
  -> 欢迎页
     -> 登录
        -> 输入邮箱 + 选择服务器
        -> 输入主密码 + 安全密钥
        -> 拉取服务器密文
        -> 本地解锁
        -> 进入保险库
     -> 创建新账号
        -> 打开网站创建账号
        -> 网站完成邮箱验证、主密码、Secret Key 和备份流程
        -> deep link 回到 PC 客户端
        -> 进入后续初始化 / 拉取数据

有本机账号
  -> 直接进入解锁页
  -> 输入主密码
  -> 从系统安全存储读取安全密钥
  -> 解锁保险库
```

## 与安全模型的关系

该流程必须遵守 `security-model.md` 的密钥边界：

1. 主密码只由用户输入，不保存、不上传。
2. 安全密钥是高熵 Secret Key 类密钥，不能被描述成找回主密码的恢复码。
3. 安全密钥不能单独解锁保险库，必须和主密码一起派生 `unlockKey`。
4. 服务器只能保存密文对象和必要元数据。
5. 受信任设备只能帮助当前设备后续解锁，不能作为跨设备恢复材料。

该流程必须遵守 `server-sync-design.md` 的产品口径：面向用户时不强调“同步”，只表达为登录服务器账号、保存到服务器、已保存到服务器和服务器版本冲突。
